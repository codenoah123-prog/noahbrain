# 다운로드 없이 브라우저에서 테스트하기

이 안내는 **GitHub Codespaces에서 소스를 빌드해 테스트하는 방법**입니다. Windows용 ZIP을 내려받거나 차단을 해제하지 않습니다. 이전 ZIP의 배포 보류는 유지되며, 이 방법을 준비했다는 사실이 Windows 백신 검증 완료를 뜻하지 않습니다.

현재 앱은 샘플 콘텐츠로 동작하는 테스트 모드입니다. **실제 인스타그램 계정 연결, 팔로우 조회, 댓글·DM 발송은 아직 구현되어 있지 않습니다.**

## 1. 비용부터 확인하기

Codespace를 만드는 작업은 사용자가 직접 진행합니다. 이 프로젝트를 준비하는 과정에서 사용자의 Codespace를 생성하거나 결제 서비스를 신청하지 않습니다.

- GitHub 개인 Free 계정에는 월 120 코어 시간과 15 GB-month 저장 공간이 포함됩니다. 2코어 환경을 단독 사용하면 계산상 최대 60시간에 해당하며, 다른 Codespace 사용량과 공유합니다. **사용자 계정의 남은 무료 제공량은 아직 확인하지 못했습니다.**
- GitHub의 **Settings → Billing and licensing**에서 Codespaces 사용량과 예산을 먼저 확인하세요. 결제 수단이 없으면 무료 제공량을 소진했을 때 사용이 차단된다는 것이 공식 안내입니다. 결제 수단이 등록된 계정은 초과 비용이 생길 수 있으므로 **유료 사용이 차단되는 예산 설정인지 확인한 경우에만** 진행하세요. 단순 알림은 과금 차단과 다릅니다.
- 이 구성은 Node 24용 공식 개발 컨테이너 이미지를 사용합니다. 사용자 지정 이미지의 저장 공간과 앱 파일도 저장 공간 사용량에 포함됩니다. 사용하지 않을 때 Codespace를 중지하면 실행 시간은 줄지만, **남겨 둔 Codespace의 저장 공간 사용은 계속 계산됩니다.**
- 추가 월 결제 0원이 목표입니다. 무료 제공량이나 차단 설정을 확인할 수 없으면 Codespace를 생성하지 마세요. 단기 검증용이며, 매일 24시간 운영하는 서버로 사용하지 않습니다.

[GitHub 공식 요금·무료 제공량 안내](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces)

## 2. 소스 실행용 브랜치 열기

1. GitHub에 로그인하고 [noahbrain의 브라우저 테스트 브랜치](https://github.com/codenoah123-prog/noahbrain/tree/codex/browser-test)를 엽니다.
2. 브랜치 이름이 **`codex/browser-test`**인지 확인합니다. 이전 `codex/windows-download` 브랜치에는 실행 ZIP이 없습니다.
3. **Code → Codespaces**를 선택합니다. 만들기 옵션에서 현재 브랜치와 **2-core**를 선택합니다. 메뉴 위치가 다르면 `… → New with options`에서 선택할 수 있습니다.
4. 무료 제공량과 과금 차단을 확인했다면 Codespace를 만듭니다. 브라우저에 VS Code 형태의 개발 화면이 열립니다.

처음 생성 시 설정된 Node.js와 SQLite를 확인한 뒤 `npm ci`, 앱 빌드, 기존 테스트를 실행합니다. 이는 Codespace 생성 후 사용자의 환경에서 실행되는 설치 절차입니다. 설치 실패가 표시되면 서버를 시작하지 말고 실패한 명령을 확인하세요.

## 3. 앱을 실행하고 열기

설치가 끝나면 브라우저 개발 화면의 터미널에서 다음 명령을 실행합니다.

```bash
npm run browser
```

이 명령은 앱을 빌드하고 화면과 API 서버를 함께 실행합니다. 서버가 준비되면 **Ports** 탭의 **3001** 항목을 찾습니다.

1. 포트의 **Visibility가 Private인지** 확인합니다. 이 앱은 별도 사용자 인증이 없으므로 Public으로 변경하지 마세요. 기본 포트 공개 범위는 Private이지만, 실제 설정은 사용자 환경에서 확인해야 합니다.
2. 해당 포트의 **Open in Browser**를 선택합니다. Codespaces가 제공한 로그인된 사용자 전용 주소로 앱이 열립니다.
3. 샘플 게시물에서 자동화를 만들고 댓글 테스트를 실행합니다. 팔로우 조건을 켜면 대기 상태와 확인 후 테스트 발송을 확인할 수 있습니다.

포트가 안 보이면 Ports에서 3001을 추가하고 Private인지 확인하세요. 앱 화면에서 서버 연결 오류가 나타나면 터미널의 `npm run browser` 프로세스가 계속 실행 중인지 확인하세요. Codespaces 주소는 직접 생성한 환경에서만 알 수 있으며, 이 저장소의 링크를 클릭하는 것만으로 앱이 실행되지는 않습니다.

## 4. 사용 후 중지하기

1. 앱 터미널에서 `Ctrl+C`로 서버를 종료합니다.
2. [내 Codespaces 목록](https://github.com/codespaces)에서 해당 환경을 **Stop codespace**로 중지합니다. 브라우저 탭을 닫는 것만으로 즉시 중지된다고 가정하지 마세요.
3. 설정·테스트 기록을 남기려면 서버를 종료한 상태에서 `data/` 폴더를 보관하세요. 데이터는 Git에 포함되지 않습니다. 사용자 파일을 GitHub에 공개하지 마세요.
4. 검증을 마치고 더 사용할 필요가 없으면 필요한 데이터를 먼저 내보낸 뒤 Codespace를 삭제하면 이후 저장 공간 사용을 줄일 수 있습니다. 삭제하면 그 환경의 보관하지 않은 데이터는 없어집니다.

## 검증 범위와 남은 작업

- 공식 Node 이미지의 태그와 레지스트리 manifest를 확인하고, 이미지 digest를 고정했습니다. 이 설정은 자동으로 앱 서버를 시작하거나 포트를 Public으로 만들지 않습니다.
- 실제 사용자의 Codespace 생성·브라우저 포워딩·과금 차단은 아직 실행하거나 검증하지 않았습니다. 앱 자체의 Linux 검증 결과와 실제 Codespace 검증을 구분합니다.
- 실제 인스타그램 연동은 별도입니다. 전문 계정과 API 권한, 댓글 이벤트, 첫 비공개 답장, 팔로우 조회·확인 후 발송의 허용 조건을 검증해야 합니다.
- API 키나 비밀번호를 채팅, 프런트엔드 코드, Git 파일에 입력하지 마세요. 관리 화면 전체를 공개하는 방식으로 실제 웹훅을 연결하지 않습니다.
